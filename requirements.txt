# Dependencies for the deployed dashboard (dashboard.py and its imports:
# geo_boundary, map_controls, province_composite, turbidity_model,
# turbidity_style). Loose lower-bound pins rather than exact versions since
# Streamlit Community Cloud's Python runtime may differ from local dev.
# DO NOT lift the starlette cap without checking the note below.
#
# starlette 1.4.0 (released 2026-08-05) added a required keyword-only argument
# to GZipResponder.__init__:
#     1.3.1  __init__(self, app, minimum_size, compresslevel=9)
#     1.4.0  __init__(self, app, minimum_size, compresslevel=9, *, thread_minimum_size)
# Streamlit subclasses that responder and calls it without the new argument, so
# any install that picks up 1.4.0 dies on every request with
#     TypeError: GZipResponder.__init__() missing 1 required positional argument
# before a single line of app code runs.
#
# This is an upstream bug, not something this project can code around: streamlit
# 1.61.0 (the newest release) still declares `starlette<2,>=0.46.0` and still
# omits the argument, so its own metadata permits the version that breaks it.
# The cap below is what actually holds the line - an exact `==` pin left the
# resolver free to settle elsewhere when something else in the tree wanted a
# newer starlette. Drop the cap only once a Streamlit release passes
# thread_minimum_size, then redeploy and confirm the app loads.
streamlit==1.60.0
starlette>=1.3,<1.4
streamlit-folium>=0.24
folium>=0.19
altair>=5.0
pandas>=2.2
numpy>=1.26
matplotlib>=3.8
# >=1.9, not >=1.4: the committed .pkl models were pickled by scikit-learn
# 1.9, and an OLDER scikit-learn cannot read a newer pickle. The old floor let
# pip resolve to a version that would fail to load the model at runtime - in
# the cloud only, where nobody sees it until the page breaks.
scikit-learn>=1.9,<2.0
joblib>=1.3
